# warehouse-map

Учёт товаров на визуальной карте склада / торгового зала.
Единицы везде — метры, ось Y вверх, углы в радианах против часовой.

> Подробно о том, как устроены маршруты, расстановка и отрисовка, — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Структура

```
crates/
  wh-core      домен + геометрия + демо-данные (shared; feature `serde`)
  wh-nav       граф видимости, кратчайший ломаный маршрут, доступность
  wh-layout    авторасстановка по востребованности
  wh-storage   трейты хранилища, InMemory, JSON-файл (обмен проектом)
  wh-demo      сквозной сценарий без GUI

  gui-core     Slint-окно + логика редактора + построение сцены (2D и изометрия)
  app-editor   desktop: gui-core в режиме Editor
  app-viewer   Android (cdylib) и desktop (bin): gui-core в режиме Viewer

  (позже)  wh-server — сервис-слой над `dyn Storage` + HTTP
```

```
wh-nav ─┐
wh-layout ─┼─► wh-core
wh-storage ┘        ▲
gui-core ───► wh-core, wh-nav, wh-layout, wh-storage
app-editor / app-viewer ──► gui-core
```

Внутри `gui-core` слои разделены так, чтобы почти всё тестировалось без окна:

| модуль     | что делает                                              | тесты |
|------------|---------------------------------------------------------|-------|
| `editor`   | состояние, инструменты, закрепление, анализ, расстановка | да    |
| `viewport` | метры ↔ пиксели, вписать, зум, сдвиг                     | да    |
| `scene`    | команды Path для 2D-плана и изометрии, тепловая окраска  | да    |
| `ui`       | Slint-окно, подписка на события, перерисовка             | —     |

## Запуск

```
cargo test --workspace          # тесты всех крейтов
cargo run -p wh-demo            # консольный сценарий
cargo run -p app-editor         # редактор (читает/пишет ./warehouse.json)
cargo run -p app-viewer         # просмотрщик на desktop
```

Если `warehouse.json` нет, открывается демо-склад (L-образный, 6 стеллажей, 8 товаров).

## Как пользоваться редактором

1. **Контур склада** → кликайте вершины. Чекбокс «Ортогонально» выравнивает рёбра по осям;
   у каждого ребра подпись длины в метрах, у курсора — «линейка» текущего отрезка.
   Клик рядом с первой точкой (или «Замкнуть контур») завершает многоугольник.
2. **Вход** → задайте точку входа (от неё считаются маршруты).
3. **Стеллаж** → выберите типоразмер, кликайте по плану. «Повернуть на 90°» меняет сторону
   выдачи — на плане это короткий «усик» на лицевой грани. Пересечения и выход за стены не допускаются.
4. **Выбор** → клик по стеллажу; «Две стороны» делает его доступным с обеих сторон.
5. Справа добавьте товары (название, ячеек, спрос).
6. **Рассчитать доступность** — стеллажи красятся от зелёного (близко) к красному (далеко),
   у выбранного рисуется маршрут от входа. Серо-красный — недостижим.
7. **Авторасстановка** — востребованное → на доступные полки. Выделите товар в списке и стеллаж
   на карте, «Закрепить» — товар остаётся на месте при следующей авторасстановке.
8. **3D вид** — изометрия, стеллажи как параллелепипеды; выбор кликом работает и там.
9. «Сохранить» / «Открыть» — JSON-файл проекта.

## Android

`app-viewer` собирается как `cdylib` с точкой входа `android_main`. Сборка по инструкции Slint
для Android (`cargo apk` или `xbuild`, нужны Android SDK/NDK и target `aarch64-linux-android`).
Проект читается из `<internal_data_path>/warehouse.json`, при отсутствии — демо-склад.
Если сборка ругается на набор фич Slint — поправьте список фич в `crates/app-viewer/Cargo.toml`
(секция `target.'cfg(target_os = "android")'`).

## Известные ограничения прототипа

* Контур нельзя править после замыкания — только нарисовать заново (стеллажи при этом удаляются).
* Стеллажи не перетаскиваются: удалить и поставить заново; поворот — по 90°.
* Товар помещается на стеллаж целиком (без деления между полками); жадная расстановка.
* Высота стеллажа в 3D — константа (`scene::SHELF_HEIGHT`), в модель не вынесена.
* Один файл проекта; сервер и БД — следующий этап.
* Размер холста отслеживается таймером (~120 мс), поэтому после ресайза окна перерисовка идёт с небольшой задержкой.
